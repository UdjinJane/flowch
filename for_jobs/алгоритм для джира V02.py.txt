## ⚙️ ALGORITHM: CONTEXTUAL DATA INTEGRATION & RELEASE PIPELINE (V5.0)

### I. OBJECTIVE
To process highly fragmented, redundant, and semi-structured log data from multiple source fragments sharing a single logical identifier. The goal is to consolidate all release/hotfix pairs into a single, canonical dataset, eliminating redundancy while preserving the context of the changes.

### II. INPUT STRUCTURE & ASSUMPTIONS
*   **Input:** A collection of XML `<source>` tags (`Context_Data`).
*   **Critical Assumption (V5.0 Improvement):** If multiple `<source>` tags share the same logical source ID or resource identifier, they must be treated as a single stream of data for parsing, rather than independent events. All extracted information will cite this unified source `[1]`.

### III. CORE FUNCTIONS & STEPS

#### 1. FUNCTION: `CONSOLIDATE_CONTEXT(Context_Data)`
*   **Input:** List of `<source>` elements.
*   **Output:** A single, cleaned string buffer (`Consolidated_Log`).
*   **Process:**
    *   Initialize `Consolidated_Log = ""`.
    *   Iterate through all `<source>` tags in `Context_Data`.
    *   Append the raw text content of each source to `Consolidated_Log`, ensuring that structural separators (e.g., newlines, headers) are maintained for readability during parsing.

#### 2. FUNCTION: `PARSE_AND_EXTRACT(Consolidated_Log)`
*   **Input:** The unified log string (`Consolidated_Log`).
*   **Output:** A dictionary mapping unique Release IDs to their associated Hotfix/Product ID and Date Range (Dictionary[str, Dict]).
*   **Process:**
    *   Initialize `Canonical_Registry = {}`.
    *   Apply a comprehensive Regular Expression pattern designed to capture the core relationship:
        `rvr-release-(?P<ReleaseVersion>[\d\.]+)-[a-z]+.*?Хотфикс Выпущено в бой \((?P<HotfixID>[a-zA-Z0-9-]+)\)`
    *   For every match:
        *   Extract `ReleaseVersion` and `HotfixID`.
        *   Identify the associated date (if available).
        *   If the pair (`ReleaseVersion`, `HotfixID`) is already in `Canonical_Registry`, *skip* or update only with newer metadata. Otherwise, store the full record: `Canonical_Registry[ReleaseVersion] = { 'hotfix': HotfixID, 'date': Date }`.
    *   *(Self-Correction:* Special handling must be implemented for non-standard pairings, such as "Mini релиз ЦГУ" or direct product release names without a preceding `rvr-release-*` structure.)

#### 3. FUNCTION: `STRUCTURE_OUTPUT(Canonical_Registry)`
*   **Input:** The clean, unique record set (`Canonical_Registry`).
*   **Output:** A structured list ready for display.
*   **Process:**
    *   Initialize two lists: `Hotfix_List` and `Release_List`.
    *   Iterate through the keys of `Canonical_Registry`:
        *   If the entry represents a modular patch (e.g., `atg`, `szn`), add it to `Hotfix_List`.
        *   If the entry represents a major product grouping or mini-release, add it to `Release_List`.
